# 言录架构

## 依赖方向

言录只依赖言据 1.2 和言序标准库。请求、数据库与 ORM 库可以依赖并注入言录；言录不反向导入这些上层库，因此不会形成循环。

请求和数据库集成通过纯字段构造器完成，没有网络连接、数据库连接或后台线程。

## 写入管线

一次`日志器.写`依次执行：

1. 验证等级并应用日志器最低等级；
2. 验证消息、字段和上下文预算；
3. 深拷贝并合并上下文与调用字段；
4. 按大小写不敏感键递归脱敏；
5. 取得时间源并建立模式 v1 记录；
6. 验证日志值图和 JSON 可编码性；
7. 若启用采样，把隔离副本交给采样器；
8. 为每个处理器生成独立副本并同步调用；
9. 返回未被处理器共享的记录，或在等级过滤/采样丢弃时返回`空`。

整个管线同步且顺序稳定。库不创建线程、任务队列或全局日志器；并发、背压、刷新和关闭生命周期由上层应用或自定义处理器负责。

## 值安全

深层值先由显式队列做非递归预检，限制节点、深度、容器和文字字节总量。预检成功后才执行受深度上限保护的递归复制与脱敏，避免恶意输入在触发库级错误前耗尽原生栈。

记录的每个典键必须是文字，值必须是 JSON/言据共同可表示的数据类型。最终记录还会实际执行一次 JSON 编码验证，从而拒绝非有限数等编码边界。

## 所有权和隔离

- 构造器复制上下文和脱敏配置；
- 子日志器共享处理器对象和显式采样器对象，使采样计数覆盖整个日志器树；
- 每个处理器获得独立记录；
- 内存处理器返回深拷贝快照；
- 自定义采样器获得独立记录。

处理器内部把传入记录视为本次调用所有。应用不应直接调用处理器协议并在调用后继续修改同一记录。

## 文件模型

文件处理器对 UTF-8 文本执行同步追加。轮转通过读取和写入备份完成，不是原子重命名；在崩溃或多个写入者同时操作时不保证事务性。需要多进程聚合、压缩、外部保留或原子切换时，应使用函数处理器接入专用日志代理。

## 扩展边界

`函数处理器`是跨模块自定义输出的推荐入口。`设采样器`采用结构化调用：对象只需提供`保留(记录)`。这是为当前语言的跨模块协议名义限制保留的稳定扩展边界。

默认处理器错误会向上游传播。`容错处理器`提供显式、可观察的降级选择，而不是全局吞掉输出错误。
