# 性能与资源预算

## 默认上限

| 项目 | 上限 |
| --- | ---: |
| 消息字符 | 16384 |
| 模块/频道/敏感键字符 | 256 |
| 单个列或典项 | 4096 |
| 合并字段 | 256 |
| 值图节点 | 8192 |
| 嵌套深度 | 8 |
| 处理器 | 32 |
| 敏感键 | 128 |
| 内存处理器记录 | 4096 |
| 单条格式化或编码记录 | 1 MiB |
| 路径字符 | 4096 |
| 轮转阈值 | 64 MiB |
| 轮转备份 | 128 |

这些上限是库级硬边界，不是配置默认建议。应用应使用远小于硬边界的字段和处理器数量。

## 复杂度

- 等级过滤为常数时间，且在复制与时间获取之前完成。
- 对一条含`n`个节点的记录，预检、复制、脱敏和编码均为`O(n)`。
- 每个处理器获得独立副本，总成本约为`O(n × 处理器数)`。
- 固定间隔采样为常数时间；采样发生在值安全检查后、处理器复制前。
- 内存处理器`记录数()`为常数时间，`各记录()`按累计内容线性复制。
- 轮转有`k`份备份时执行最多`O(k)`次文件复制；不适合高频大文件多进程写入。

默认全量日志器跳过采样器副本和动态调用。只在明确调用`设采样器`或`固定采样`后启用采样路径。

## 性能回归工作负载

`benchmarks/批量结构化日志.yx`在默认一百万执行步预算内同步建立、验证、脱敏、JSON 格式化并保存 128 条嵌套结构化记录。发布门禁在言序 1.1.6 和当前稳定版中分别执行树解释器、字节码 VM，并比较可观察结果。

该文卷是回归工作负载，不是跨机器吞吐基准。真实容量规划应在目标处理器、磁盘、字段形状和日志等级下测量。

## 调优建议

1. 在日志器上尽早提高最低等级，避免无用记录进入管线。
2. 对高频低等级事件使用固定采样，并保护警告或错误等级。
3. 减少处理器数量和重复的大上下文。
4. 用`记录数()`检查内存处理器，不频繁请求完整快照。
5. 高吞吐文件写入使用函数处理器接入单写入者代理；不要让多个进程共享内置文件处理器。
